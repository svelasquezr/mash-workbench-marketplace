# 0006: the scripts do not trust a committed file, an argument or an old copy

## Context

An audit of the plugins found six ways in which data from a repository, from a session or from an old plugin version changed what a script did. Each one is a security bug. The conditions, the incorrect result and the expected result follow.

1. **Python modules from the current folder.** A project folder contained a file `datetime.py` or `re.py`. `backlog-stale.sh` gave its Python program to `scripts/python.sh` on standard input, and Python put the current folder first on its module path. Python ran the file from the project. The expected result is that plugin Python imports only the standard library and the files of the plugin.
2. **A committed file selected the place of a write.** The committed file `.claude/mash-workbench/settings` contained `escapes=../victim/.claude/rules`. `escape-add.sh` wrote the escape file and a `README.md` in that folder, which is outside the repository. A committed symbolic link at `.claude/mash-workbench`, at the escapes folder, at its `README.md`, at `reviews.log` or at the backlog file had the same effect. `backlog-path.sh` did no check of `MASH_WORKBENCH_BACKLOG`. The expected result is that only the user selects a place outside the repository.
3. **An argument named a file to read or to write.** `escape-add.sh --body-file <file>` copied a file that the session can read, for example a private key, into the escapes folder. `backlog-add.sh --file <path>` appended a line to a file at a path of the caller. With an allow rule from [0005](0005-exact-path-allow-rules.md), Claude Code ran these commands with no prompt. The expected result is that an argument cannot make the script open a different file.
4. **Old plugin versions.** The user accepted the allow rules of one plugin version and then updated the plugin. Claude Code kept the folder of the old version in its plugin cache. The old rules continued to approve the scripts of the old version, also when the new version corrected a security bug in them. The expected result is that an old copy does not run with no prompt.
5. **A range was read as a git option.** The session gave the range `--output=<file>` to `reviewers-for-change.py`. The router gave the text to `git diff`, and git wrote the file. The expected result is that git reads the text only as a range.
6. **A name from the config was used as a path.** `.claude/reviewers.toml` named the reviewer `../../x`. The router read the file `x.md` outside the agents folder, and it printed the `model:` value of that file in an error message. The expected result is that the router reads agent files only in the agents folders.

## Decision

1. **Isolated Python.** `scripts/python.sh` starts the interpreter, and its version probe, with `-I`. The interpreter also gets `-B`, and the script sets `PYTHONSAFEPATH=1` and `PYTHONDONTWRITEBYTECODE=1`. Python then does not import from the current folder or from the folder of the script, and it ignores `PYTHONPATH` and the user site-packages. The router adds its own folder to the module path, because its modules are there.
2. **Who selects a place outside the repository.** `mash-settings.sh path <dir> escapes|backlog` gives the place of the escapes folder and of the backlog file. It removes `.` and `..` from the path as text before the checks, and it prints that path, so the path that the checks see is the path that the script writes. It accepts a place outside the main worktree only from `settings.local` or from the environment variable. It refuses such a place with exit code 6 when the committed `settings` file names it. A `settings.local` file that git tracks is a committed file too, because a repository can commit one; `set --local` does not write a tracked `settings.local`. The message tells the session to ask the user and then to write the value to `settings.local`.
3. **Symbolic links.** The scripts refuse, with exit code 6, a symbolic link at the home folder `.claude/mash-workbench`, a `.claude` link that goes out of the main worktree, a path that the user wrote in the repository and that a link moves out of the repository, and a link at the escapes folder's `README.md`, at `reviews.log`, at the backlog file, at a settings file and at an old ledger file. They also refuse a path that contains `\`, because the path checks split a path only at `/`. The reports do not read an escape file that is a symbolic link.
4. **The backlog has the checks of the escapes.** `backlog-path.sh` uses `mash-settings.sh path`, and `backlog-add.sh` uses the new `check-backlog-path`. The backlog file has a `repo:` line below its title, and a file outside the repository with a different owner is refused. The backlog stays one file.
5. **No argument names a file.** `escape-add.sh` takes the body as text (`--body <text>`). It does not read standard input for one record, because a redirect from a file of the project (`< .env`) gets no prompt from Claude Code. `--batch` reads only standard input, and it records only text that has the block format. `--body-file`, `backlog-add.sh --create` and `backlog-add.sh --file` are removed; each one stops with exit code 2 and tells the replacement.
6. **An old copy refuses to run.** `scripts/plugin-current.sh` reads `installed_plugins.json` next to the plugin cache. When the folder of the script is in the cache, an entry of that file must name the folder. The entry counts only when it is for the user, or for the project of the current folder (the folder, the top folder of its git checkout, or the main worktree): the file can list old versions for many old projects. With no such entry, the script stops with exit code 6. `escape-add.sh`, `review-log.sh` and `backlog-add.sh` run this check first.
7. **Old rules must go.** `permission-rules.sh` prints no `add:` line while a `remove:` line is necessary. It reads the name of each list (`allow`, `deny`, `ask`), and only a rule in an `allow` list is a `present:` or `remove:` rule. The setup text tells the session to remove the old rules first. This is the only protection for the scripts of version 0.5.1 and earlier, which do not have the check of item 6.
8. **One rule script for the two plugins.** `permission-rules.sh` is the same file in `review-routing` and in `mash-workbench`. In `mash-workbench` it offers one rule, for `backlog-add.sh`, in the shape of 0005.
9. **Text that goes to git.** The router refuses a range that starts with `-` or contains a space. `review-log.sh` refuses a revision that starts with `-`, and it gives only full commit ids from the log to git.
10. **Names from the config.** The router does not use a reviewer name as a file name when the name contains `/` or `\` or starts with `.`, and it does not read an agent file that is a symbolic link.

## Options that we did not select

- **Only `PYTHONSAFEPATH=1`.** It removes the current folder from the module path. Cons: `PYTHONPATH` in the environment continues to add folders. `-I` also ignores that variable.
- **Refuse each place outside the repository.** Pros: no check of the source is necessary. Cons: a user cannot keep escapes in a folder that stays when the clone is deleted. 0004 permits that folder.
- **Ask the user in the script.** A script cannot ask a question in a session with no user. The exit code and the message give the question to the session, and `settings.local` holds the answer.
- **A body file in a private folder that the skill writes.** Cons: a session in a linked worktree cannot write in the main worktree's `.claude/` without a prompt, and each other folder is a folder that a different program can write to. Text in the argument needs no file.
- **Only the setup text for old rules.** Cons: a user who does not do setup again keeps the old rules. The check of item 6 does not need the user.
- **A check of `<repo-root>` against the current folder.** A rule approves a record in each repository that the argument names. Cons of the check: a session that starts in a folder above its repositories cannot record. We did not make this change; it is a decision for the owner.

## Pros and cons

- Pros: a committed file, a symbolic link or an argument cannot move a write out of the repository or copy a file into it. A test plants each of these cases.
- Pros: after an update, an old copy of the three scripts with rules does not run, also when the old rules stay.
- Pros: `backlog-stale.sh` does not use Python, so `mash-workbench` needs Python only for `past-friction.py`.
- Cons: a user on Windows must write a path in the settings with `/`.
- Cons: the interface changes. A session that uses `--body-file`, `--batch <file>`, `--create` or `--file` gets exit code 2 with the new form. A user who has a symbolic link in the repository as the escapes folder must set the real path in `settings.local`.
- Cons: a repository in which `.claude` is a symbolic link to a folder outside the repository cannot use the home folder. The scripts stop with exit code 6.
- Cons: the environment variables `REVIEW_ROUTING_ESCAPES`, `MASH_WORKBENCH_BACKLOG` and `MASH_PYTHON` have the trust of the user. The `env` block of a committed `.claude/settings.json` can set them after the user accepts the workspace-trust dialog of Claude Code. At that time the same file can also add hooks, so we accept this.
- Cons: `plugin-current.sh` reads the project of a session from the current folder. A person who runs a script by hand from a different folder, with a plugin that is installed only for one project, gets exit code 6.
- Cons: `plugin-current.sh` knows the cache layout of one Claude Code version (2.1.330). When the layout is different, or when the registry contains no `installPath`, the check lets the copy run. A session that started before an update gets exit code 6 from the old copy until the user starts a new session.
- Cons: the check of item 6 is not in version 0.5.1 and earlier. For those versions, only the removal of the old rules helps.
- Cons: `<repo-root>` is an argument. A rule approves a record in each repository on the machine that has a place selected. We accept this gap (see the options).
- Cons: `--batch -` reads standard input. Claude Code gives no prompt for a redirect from a file in the folders of the session, so a file there that has the block format can become escape files. A file with a different format is refused, and none of its text is written.
- Cons: outside a git repository, `backlog-add.sh` has no settings and no path checks. There, the `<repo-root>` argument and a relative `MASH_WORKBENCH_BACKLOG` select the place. The script only refuses a symbolic link that moves the write out of that folder.
- Cons: the checks compare paths with exact letter case. We did not test a file system that ignores case, or Git Bash.
- Cons: the body text goes through the command line, so the session must quote it. A body with `$( )` or a backtick in double quotes gets a prompt from Claude Code. This is a safe failure.
- Cons: `permission-rules.sh` reads only two settings files. The user must remove old rules from other files by hand.
- Cons: a reviewer agent file in the repository can give itself more tools or a permission mode, and the router does not examine these keys. The `reviewer-guard` hook is a guard against accidents and not a security boundary. We did not change this.
