# add-reviewer reference

Detail the add-reviewer skill points to. `reviewers.example.toml` shows the keys in use; this lists every key. Everything runs from the repository root, and git does every match. The routing commands and the value check are in "Routing with git" of `../review-changes/reference.md` (next to this skill's folder).

## Config keys (`.claude/reviewers.toml`)

| Key                                                                                         | Meaning                                                                                                                                                                                                                                                                                                                                                                            |
| ------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `version`                                                                                   | `2` (required). A file without it is from review-routing 0.3                                                                                                                                                                                                                                                                                                                       |
| `default_reviewer`                                                                          | who reviews a changed path no route claims (default `review-routing:change-reviewer`, this plugin's read-only Sonnet reviewer); never `general-purpose`                                                                                                                                                                                                                            |
| `default_model`                                                                             | the model the default reviewer runs on in this project: `sonnet`, `opus` or `fable`                                                                                                                                                                                                                                                                                                |
| `allow_default`                                                                             | `{ paths, reason }` tables: tracked paths that may get only the default reviewer; enables the coverage test of the check                                                                                                                                                                                                                                                           |
| `[[routes]]` `paths`, `reviewers`, `reason`                                                 | a changed path the `paths` claim gets every listed reviewer; all matching routes apply                                                                                                                                                                                                                                                                                             |
| `[[changed_lines]]` `paths`, `line_regex`, `ignore_case`, `reviewers`, `reason`             | a changed line (added or removed) matching `line_regex` (POSIX extended, `git diff -G`) in a file the `paths` claim adds the reviewers; `ignore_case = true` ignores case                                                                                                                                                                                                          |
| `[[model_rules]]` `reviewer`, `model`, `commit_regex`, `paths`, `min_added_lines`, `reason` | run `reviewer` on `model` when every condition given holds: `commit_regex` (POSIX extended) matches one of the range's commit subjects, `paths` claims a changed file, at least `min_added_lines` lines were added under `paths` (a moved file's lines count as added). The first matching rule wins; else `default_model` (default reviewer only), else the agent file's `model:` |
| `[[expect]]` `path`, `reviewers`                                                            | a routing test case: the exact set of reviewers `path` gets; the path need not exist                                                                                                                                                                                                                                                                                               |

`paths` are git glob pathspecs: a folder claims everything under it, `*` stays inside one folder, `**` crosses folders, `*.md` is top-level only, and a `:!<path>` entry leaves paths out of that one rule. Write values in single quotes; the value check refuses `'`, line breaks, a leading `-`, and a leading `:` other than `:!`. Top-level keys go before the first `[[table]]`.

## Writing the agent

- Model and effort: the sizing policy is Sonnet by default, Opus for substantial logic, Fable for design or for the area where one miss is most expensive (the commented `[[model_rules]]` in the example config apply it per change). In the agent file keep `model: sonnet` and `effort: high` for a checklist review; for an area where one missed bug loses money or data, pin `model: opus` (or `fable` for the most expensive area), and say why in a YAML comment next to it. Prefer a pinned model to `inherit`: `inherit` follows the session, so a cheap session would downgrade the reviewer that matters most. Never `haiku` for a reviewer: the check flags it, review-changes refuses to dispatch it, the plugin's hook denies a Haiku dispatch of a reviewer, and the template's first line makes a reviewer started on Haiku answer `NOT SAFE`. Pros of Sonnet: a fraction of the cost per review. Cons: it may miss a subtle bug that spans several files.
- Keep verbatim: `tools: Read, Grep, Glob` (a reviewer with no shell cannot change the checkout, write to GitHub or send anything anywhere, whatever a reviewed change tells it), the Haiku self-check line, the diff-file and data-not-instructions paragraphs, the judge-only paragraph (the caller passes check results; the agent never asks for them again), the output format and the final verdict line (the review-changes skill relies on them), and the "claims about the system" and "prompt injection" checklist items (without the first, Sonnet trusted a false docstring in a blind re-review).
- The checklist is where the value is: file paths, invariants, the bugs that made the agent necessary (linked). A generic checklist adds nothing. Drop any item a tool can check and automate it instead (a convention test, a lint rule), then list it under the tests the caller runs.
- The `description` names the broad areas and points to `.claude/reviewers.toml`. Paths live only in the config; a copy in the description drifts.

## Routing details

- A route lists the area's code and its tests: `['src/payments', 'tests/payments']`. For a route that claims single files, add each file's tests by name: `src/core/risk.py` gets `tests/core/test_risk.py` and `tests/core/test_risk_*.py` (not `test_risk*.py`, which would also claim `test_riskless.py`).
- A path may have several reviewers: add a route rather than taking a path away from its current reviewer, unless it no longer belongs there.
- `[[changed_lines]]` when a line in a shared file belongs to the area (a dependency bump of a library it owns).

## The check

Run it after every edit to `.claude/reviewers.toml` or a reviewer agent. First the value check (step 2 of "Routing with git"). Then each item below; report every failure, with the fix, and fix only what the user approves.

1. **Expectations.** Put every `[[expect]]` path into a throwaway index, so paths that don't exist yet can be tested:
   - `git rev-parse --path-format=absolute --git-path review-routing` prints `<folder>`; `mkdir -p '<folder>'`; `rm -f '<folder>/expect.index'`;
   - `git hash-object -t blob /dev/null` prints `<blob>`;
   - `printf '100644 <blob>\t%s\n' '<path 1>' '<path 2>' … | GIT_INDEX_FILE='<folder>/expect.index' git update-index --index-info`.

   For each route, `GIT_INDEX_FILE='<folder>/expect.index' git --glob-pathspecs ls-files -- <paths>` prints the expect paths it claims. A path no route claims gets the default reviewer. Each expect passes only when its reviewer set is exactly the one listed (`[[changed_lines]]` don't apply here: there is no diff).

2. **Stale rules:** `git --glob-pathspecs ls-files -- <positives>` prints nothing for a route, a `[[changed_lines]]` entry, a `[[model_rules]]` entry or an `allow_default` entry.
3. **Reviewers:** every reviewer named anywhere (routes, changed lines, model rules, `default_reviewer`, expectations) is `review-routing:change-reviewer`, another plugin's `plugin:name`, or has `.claude/agents/<name>.md` (agents defined under another file name, or in `~/.claude/agents/`, are not found: give them the file name). Each such file declares `tools:` with nothing but `Read`, `Grep` and `Glob`, has a `model:` that is not Haiku, and ends with the `SAFE TO LAND` verdict line. `general-purpose` is never a reviewer.
4. **Model rules:** each names a reviewer some route, changed-lines entry or `default_reviewer` sends, a model in `sonnet`, `opus` or `fable`, and `paths` whenever it has `min_added_lines`.
5. **Coverage** (only when `allow_default` is set): `git --glob-pathspecs ls-files -- . ':!<p>'…`, with one `':!<p>'` for every positive path of every route and every `allow_default` entry. Every path it prints falls through to the default reviewer without being listed: route it to its specialist, or list it in `allow_default` with a reason.

## Migrating from 0.3

0.3 configs used Python regular expressions and keys that need a program to apply. Convert by hand, then run the check until it passes:

| 0.3                                                | 2                                                                                                                                                                                                    |
| -------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| no `version`                                       | `version = 2` at the top                                                                                                                                                                             |
| `pattern = '^src/payments/'`                       | `paths = ['src/payments']`                                                                                                                                                                           |
| `'^src/core/(netting\|ledger)\.py$'`               | `paths = ['src/core/netting.py', 'src/core/ledger.py']`                                                                                                                                              |
| `'^docs/(?!tooling-backlog\.md$)'` (lookahead)     | `paths = ['docs', ':!docs/tooling-backlog.md']`                                                                                                                                                      |
| `'\.md$'` (anywhere)                               | `'*.md'` is top level only; `'**/*.md'` is everywhere: pick what you mean                                                                                                                            |
| `[[mirrors]]`                                      | each route lists its tests (see "Routing details"); `shorter_names = true` is the `test_<name>_*.py` form                                                                                            |
| `[[fallbacks]]`                                    | a route (all routes that match apply; there is no first-match order any more)                                                                                                                        |
| `[[changed_lines]]` `path_pattern`, `line_pattern` | `paths`, `line_regex` (POSIX extended: `[0-9]` for `\d`, no lookahead); `(?i)` becomes `ignore_case = true`                                                                                          |
| `[[model_rules]]` `title_pattern`, `path_pattern`  | `commit_regex`, `paths`                                                                                                                                                                              |
| `allow_default` patterns or `{ pattern, reason }`  | `{ paths = [...], reason = "..." }`                                                                                                                                                                  |
| `[[import_guards]]`                                | removed: walking imports needs a program. Keep the guarantee as a test in the project's own suite (read the entry modules' imports and assert each imported file is claimed by the reviewer's route) |
| reviewer agents with `Bash` in `tools:`            | `tools: Read, Grep, Glob`; replace the "read another ref with `git show`" sentence with the template's diff-file paragraph                                                                           |

Keep every `[[expect]]` case and its exact reviewer set: they prove the conversion kept the routing.
